# 从大模型推理看计算范式变革：为什么需要数据流芯片？

## 引言：算力需求的结构性转移

在过去十余年中，深度学习的训练与通用推理几乎被 SIMT（单指令多线程）架构的 GPU 牢牢垄断。然而，随着大语言模型（LLM）的全面落地，AI 的计算重心正在经历从“万卡集群离线预训练”到“线上高频自回归推理”的重大转移。

在实际生产环境中，自回归生成（Decode）阶段占据了用户请求 80% 以上的时间。这一阶段的计算特性使得芯片系统的性能瓶颈不再取决于纸面上的峰值浮点算力（Peak FLOPS），而是受制于底层存储架构的物理搬运能力。面对低并发与严苛交互时延的约束，传统 GPU 正在撞上不可逾越的物理之墙，而**数据流（Dataflow / Spatial Architecture）架构**的复兴，正是计算范式顺应算法物理特征演进的必然结果。

---

## 一、 大模型推理的底层物理诉求与阶段割裂

大模型推理不是单一连续的计算过程，而是由两个代数形态截然相反的阶段构成。

```
                  ┌──────────────────────────────────────────────┐
                  │            大模型推理的两大计算阶段           │
                  └──────────────────────┬───────────────────────┘
                                         │
                 ┌───────────────────────┴───────────────────────┐
                 ▼                                               ▼
   【Prefill 阶段: 吞吐优先】                       【Decode 阶段: 延迟优先】
   • 核心算子: 稠密矩阵乘 (Dense GEMM)              • 核心算子: 矩阵乘向量 (GEMV)
   • 算术强度: 较高 (数十~数百 FLOPs/Byte)          • 算术强度: 极低 (仅 1~2 FLOPs/Byte)
   • 物理瓶颈: 纯浮点算力 (Compute-Bound)          • 物理瓶颈: 显存访存带宽 (Memory-Bound)
   • 核心指标: 首字延迟 (TTFT)                     • 核心指标: 字间生成速度 (TPOT)

```

### 1.1 Prefill 阶段：稠密矩阵乘与计算受限（Compute-Bound）

* **计算范式：** 稠密矩阵乘大矩阵（Dense GEMM）。用户输入的 Prompt（数十至数千个 Token）被一次性并行展开，输入序列的所有词元在前向传播中同时建立注意力并生成初始 KV Cache。
* **算术强度：** 随输入序列长度 $N$ 快速上升，通常可达数十至数百 $\text{FLOPs/Byte}$。
* **物理瓶颈：** 处于典型的 **计算受限（Compute-Bound）** 区间。只要硬件堆叠足够的 Tensor Core 阵列并拉高主频，就能显著压低首字时延（Time to First Token, TTFT）。

### 1.2 Decode 阶段：矩阵乘向量与访存受限（Memory-Bound）

* **计算范式：** 矩阵乘向量（GEMV）。自回归算法每前进一步，只处理最新生成的 **1 个 Token**，但为了完成各层的线性投影与前馈计算，系统必须把**整个模型的全部权重从显存中全量读取一遍**。
* **算术强度断崖：** 发生断崖式下跌。以 FP16 精度为例，每个参数占 2 字节，一次前向计算消耗约 2 次浮点操作（乘加），权重侧的理论算术强度仅为：

$$I \approx \frac{2 \times P \text{ FLOPs}}{2 \times P \text{ Bytes}} = 1 \text{ FLOP/Byte}$$


* **物理瓶颈：** 硬件处于极端的 **访存受限（Memory-Bound）** 状态。决定每秒吐字速度（Time Per Output Token, TPOT）的核心瓶颈，已经与算力上限脱钩，纯粹取决于内存物理接口以多快的线速把权重送达计算单元。

### 1.3 Roofline 视角下的物理鸿沟

以配备 80GB HBM3、内存带宽为 3.35 TB/s、Dense FP16 算力约为 989 TFLOPS 的 NVIDIA H100 SXM 为例：

* 其计算与访存的饱和平衡拐点（Roofline Knee Point）为：

$$I^* = \frac{989 \times 10^{12} \text{ FLOPs/s}}{3.35 \times 10^{12} \text{ Bytes/s}} \approx 295 \text{ FLOP/Byte}$$


* 在 Batch=1 的 Decode 阶段，实际算术强度仅为 **$1 \text{ FLOP/Byte}$**，远低于 $295$ 的饱和点。这在物理层面上宣判：**在单流自回归场景下，GPU 绝大部分计算单元注定无法被饱和利用。**

### 1.4 下一代 AI 应用对“低 Batch 单流时延”的硬约束

在实际业务场景中，为了追求吞吐而无限制拼批（Batching）的时代正在过去：

1. **端侧与个人设备：** 智能座舱、AI PC、机器人等场景天然面向单一物理用户，请求**恒为 Batch=1**，无法靠多用户并发去分摊权重读取开销。
2. **拟真全双工交互：** 人类对对话停顿的感知极限通常在 200~300ms。扣除 ASR 语音识别、TTS 语音合成与网络 RTT，留给 LLM 的单步思考与吐字时间预算只有 **数十毫秒**。
3. **深度思考链 Agent（Reasoning Chains）：** 复杂逻辑推理模型需在后台自发生成数千字中间 Token。如果单流生成速度停留在 30~40 Tokens/s，用户等待时间将以分钟计；单流吐字必须提升到 **300 ~ 800+ Tokens/s**，才能支撑思考链的实时交付。

## 二、 传统 GPU 面对低 Batch Decode 的“结构性内伤”

现代 GPU 建立在 SIMT（单指令多线程）与分层存储体系之上，这一微架构在面对低 Batch 自回归时暴露了三项根本性矛盾：

### 2.1 延迟掩盖机制在低并发下彻底失效

GPU 的设计精髓是用庞大的线程并发（Thread-Level Parallelism）来掩盖片外访存延迟：当 Warp 0 发起 HBM 读取被挂起时，硬件调度器以单周期速度切换至 Warp 1、Warp 2 继续计算。

但在 Batch=1 场景下，**线程池中可用的活跃 Warp 数量急剧萎缩**。缺乏足量的计算线程填补漫长的 HBM 访存时延，数以万计的算术逻辑单元只能陷入停顿等待（Stall）。

### 2.2 实际吞吐受制于 HBM 物理带宽下限

以单卡可完整容纳的 **LLaMA-3-8B（FP16 权重约 16GB）** 为例，在配备 3.35 TB/s 带宽的 H100 上执行 Batch=1 Decode：

* 仅仅全量读取一次模型权重，物理传输时间的下限为：

$$t_{\text{weight}} \ge \frac{16 \text{ GB}}{3350 \text{ GB/s}} \approx 4.78 \text{ ms/Token}$$


* 对应的单流生成理论上限约为 **209 Tokens/s**（若计入 KV Cache 读写、Attention 计算、片内总线延迟及驱动调度，实际测试通常在 100~150 Tokens/s 左右）。
* 此时，GPU 的模型实际算力利用率（MFU）通常跌落至 **10% ~ 20%**。用户购置了昂贵的浮点算力，绝大多数硅片面积却在充当低效的内存搬运工。

### 2.3 沉重的“冯·诺依曼税”引发能效危机

通用处理器为了维持灵活的可编程性，必须支付高昂的控制面开销：

* **控制面晶体管消耗：** 指令提取（Fetch）、指令译码（Decode）、分支预测、乱序调度与 Warp 仲裁电路持续吞噬动态功耗。
* **数据搬运能量代差：** 在先进半导体工艺下，一次 16-bit 浮点 MAC 计算消耗能量约为 **0.1 ~ 0.5 pJ**，而将数据通过长距离硅中介层与高频 SerDes 从片外 HBM 搬运到核心，能耗高达 **100 ~ 200 pJ**。
* 在小算术强度下，GPU 大部分电能消耗在指令管理与宏观物理走线的电荷充放上，导致单 Token 能耗居高不下。

## 三、 数据流芯片的微架构解密：空间计算如何破局？

与 GPU 的“时间复用（Temporal）”不同，数据流芯片采用了“空间计算（Spatial Computing）”的全新微架构设计范式（如 Groq LPU、Cerebras 等代表方案）：

```
传统 GPU (时间复用):
[计算工位 (SM)] ──第 1 拍: 算 QKV ──► [写回显存/中间缓存]
                ──第 2 拍: 算 Softmax ◄── [从显存/缓存拉回]
                ──第 3 拍: 算 FFN ──► [再次写回]

数据流架构 (空间平铺流水线):
[输入数据] ──► [PE 0: 算 QKV] ──(片内微米级短线)──► [PE 1: 算 Softmax] ──(片内短线)──► [PE 2: 算 FFN] ──► [输出]
              (计算单元固定角色，数据像流水穿过芯片，无中间落盘)

```

### 3.1 空间流水线替代时间复用：中间激活零回写

在数据流芯片中，算子图被物理“平铺”在二维处理单元（PE）阵列上。

* **波前流动：** 输入张量像自来水一样穿过物理阵列，PE0 计算完成后，直接通过片上微米级的相邻金属走线将结果注入下游的 PE1，中间激活值驻留在本地 FIFO 或局部 Scratchpad 中，**彻底消除了反复向外部大内存回写中间结果的开销**。

### 3.2 片上分布式超大近存（SRAM）：彻底抹平访存鸿沟

数据流芯片通常舍弃片外 HBM，转而在芯片表面集成 **数百 MB 至数 GB 的分布式片上 SRAM**：

* 片上 SRAM 直连计算阵列，能够提供高达 **数十至数百 TB/s** 的片上总互联带宽（例如 Groq 第一代芯片即提供 80 TB/s 片上带宽），直接将访存带宽提升 1~2 个数量级。
* 物理距离被压缩在微米级别，数据读取能耗从 HBM 的数百皮焦断崖式下跌到 **几皮焦（pJ）**，从物理源头瓦解了“内存墙”。

### 3.3 周期严格确定性（Cycle-deterministic）：消灭长尾抖动

静态数据流芯片（以 Groq TSP/LPU 为典型）将调度权从芯片内部完全剥离，上移至编译器：

* **无硬件动态仲裁：** 芯片内部没有 Warp 调度器、没有动态分支预测、没有硬件缓存一致性维护。
* **编译器时钟级排程：** 编译器在离线编译时，精确规划每个数据包在第几个时钟周期流向哪个 PE 坐标。
* **零抖动交付：** 硬件执行时没有冲突、没有死锁、没有 Cache Miss 引起的重试。在运行稳定的自回归任务时，P99 尾部延迟与 P50 中位数延迟之比能够**趋近于绝对平直的 1.0**。

## 五、 数据流架构的客观代价与工程妥协

数据流芯片在换取极致单流延迟与确定性的同时，也承担了极其严苛的工程代价：

### 5.1 SRAM 容量极限与集群堆叠成本（CapEx）

在先进半导体工艺节点（如 4nm/3nm）下，SRAM 晶体管的微缩已几乎停滞。单颗芯片能集成的 SRAM 容量上限通常只有几百 MB。

* 单颗数据流芯片无法装下几十 GB 甚至几百 GB 的大模型全量权重。
* **高昂的集群门槛：** 运行一个全尺寸 70B 模型，必须使用数十甚至上百颗芯片通过高速片间互联网络（C2C Cables）组成分布式 SRAM 池。整机系统的初始采购硬件成本与互联拓扑复杂度被显著拉高。

### 5.2 编译器是最高维度的技术壁垒

数据流芯片的成败完全系于编译器：

* 编译器必须在一张庞大的硬件物理网格上，同时解决模型计算图的 **空间切片（Tiling）、算子放置（Placement）、无拥塞寻路（Routing）与时钟周期排程（Scheduling）**，这属于高维度的 NP-Hard 组合优化问题。
* 面对包含动态上下文长度、稀疏激活条件分支以及 **MoE（混合专家模型）动态路由** 的复杂任务，纯静态编排极易产生流水线空泡（Stall Bubbles），对编译系统的动态适应性提出了巨大挑战。

## 六、 终局预测：Prefill 与 Decode 走向物理彻底解耦（P/D Disaggregation）

体系结构演进的规律表明，极少存在能够全盘通吃所有工作负载的“完美芯片”。未来的大模型计算基础设施，必然走向 **Prefill 与 Decode 物理彻底分离的异构解耦系统**。

```
                               【数据中心 P/D 解耦异构系统拓扑】

            ┌────────────────────────────────────────────────────────┐
            │                  用户/业务请求进入 (Prompt)             │
            └───────────────────────────┬────────────────────────────┘
                                        │
                                        ▼
    ┌────────────────────────────────────────────────────────────────────────┐
    │ 1. Prefill 算力节点: GPU 的绝对主场 (Dense GEMM / Compute-Bound)       │
    │    • 硬件形态: 搭载大容量 HBM 的通用 GPU 节点                          │
    │    • 核心任务: 吞下长 Prompt，打满 TFLOPS 纯算力，极速生成 KV Cache      │
    └───────────────────────────────────┬────────────────────────────────────┘
                                        │
                                        │ 极速流式交付 KV Cache
                                        │ (走 PCIe P2P / CXL Fabric / RoCE 网络)
                                        ▼
    ┌────────────────────────────────────────────────────────────────────────┐
    │ 2. Decode 算力节点: 数据流芯片的终极舞台 (GEMV / Memory-Bound)          │
    │    • 硬件形态: 分布式大 SRAM / 空间流式流水线专用芯片/卡                │
    │    • 核心任务: 承接初始 KV Cache，以极高单字速率与极低能耗逐字生成回复   │
    │    • 运行特征: 极低 TPOT、极低能耗、近零抖动实时交付                    │
    └───────────────────────────────────┬────────────────────────────────────┘
                                        │
                                        ▼
            ┌────────────────────────────────────────────────────────┐
            │                   极速低时延流式响应返回用户            │
            └────────────────────────────────────────────────────────┘

```

1. **Prefill 计算池（GPU 统领）：** 依赖其在稠密计算与大容量 HBM 上的深厚积累，专注于并行消化长文本 Prompt，将 TTFT 压到极致；
2. **中间状态流式交付：** 初始计算完成后的 KV Cache 通过超高速总线（如 PCIe P2P、CXL 共享内存或专用 RDMA 网络）跨节点推送给 Decode 节点；
3. **Decode 计算池（数据流芯片统领）：** 接收到初始状态后，专用数据流加速节点依靠片上超大带宽 SRAM 和空间流水线，以极高频率自回归吐字，释放无抖动、极速的实时生成体验。

## 结语

大模型推理的底层算力矛盾，本质上是**自回归生成极低的算术强度与通用芯片落后的访存供给之间的物理冲突**。

数据流芯片不是对通用 GPU 生态的全面否定，而是针对小 Batch、低时延自回归任务开出的一剂精准猛药。它通过空间计算取代时间复用，用片上超高带宽抹平访存鸿沟，用编译期确定性消灭运行期控制能耗。理解这种微架构与物理法则的共生演化，是我们在大模型落地深水区中，构建真正具备成本效益与极致体验的下一代 AI 算力底盘的关键钥匙。
