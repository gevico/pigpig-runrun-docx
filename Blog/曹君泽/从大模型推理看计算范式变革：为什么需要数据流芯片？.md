# 从大模型推理的物理本质看计算范式变革：为什么需要数据流芯片？

## 引言：算力需求的结构性转移

在过去十余年中，深度学习的计算底座几乎完全建立在通用图形处理器（GPU）及其 SIMT（单指令多线程）体系之上。依靠成千上万个线程并发与高位宽外部存储体系，GPU 完美支撑了万卡规模的模型预训练与大并发离线计算。

然而，当大语言模型（LLM）从研发训练全面走向在线部署时，系统的核心矛盾发生了迁移。在大模型在线服务的完整生命周期中，自回归逐字生成（Decode）阶段占据了单次请求绝大部分的物理耗时。在这一阶段，系统吞吐与延迟不再受制于芯片标称的峰值浮点算力（Peak FLOPS），而是严格受限于存储子系统在单位时间内向计算核心搬运参数的能力。面对低并发（Batch=1）与严苛实时交互的物理约束，传统 GPU 的微架构机制显现出结构性瓶颈。探索面向空间计算的数据流（Dataflow / Spatial Architecture）芯片 正式顺应次趋势。

## 一、大模型推理的底层物理诉求与阶段割裂

大模型推理不是单一连续的同质计算，而是由两个代数形态与受限类型截然相反的阶段构成。

```text
                  ┌──────────────────────────────────────────────┐
                  │            大模型推理的两大计算阶段           │
                  └──────────────────────┬───────────────────────┘
                                         │
                 ┌───────────────────────┴───────────────────────┐
                 ▼                                               ▼
   【Prefill 阶段: 吞吐优先】                       【Decode 阶段: 延迟优先】
   • 核心算子: 稠密矩阵乘 (Dense GEMM)              • 核心算子: 矩阵乘向量 (GEMV)
   • 算术强度: 较高 (数十~数百 FLOPs/Byte)          • 算术强度: 极低 (仅 1~2 FLOPs/Byte)
   • 物理瓶颈: 纯浮点算力 (Compute-Bound)          • 物理瓶颈: 显存访存带宽 (Memory-Bound)
   • 核心指标: 首字延迟 (TTFT)                     • 核心指标: 字间生成速度 (TPOT)
```

### 1.1 Prefill 阶段：高算术强度与计算受限（Compute-Bound）

* **计算范式：** 稠密矩阵乘（Dense GEMM）。用户输入的 Prompt（数十至数千个 Token）被一次性并行展开，模型在前向传播中同时建立注意力机制并生成初始 KV Cache。
* **算术强度：** 随输入序列长度 $N$ 快速上升，通常在数十到数百 $\text{FLOPs/Byte}$ 之间。
* *特点：** 处于典型的计算受限（Compute-Bound）区间。此时权重数据读入一次即可被序列中的多个 Token 充分复用，只要芯片拥有足够密度的浮点运算管线（Tensor Core）和高主频，就能显著压低首字时延（Time to First Token, TTFT）。

### 1.2 Decode 阶段：极低算术强度与访存受限（Memory-Bound）

* **计算范式：** 矩阵乘向量（GEMV）。自回归算法的本质是“根据已知序列预测第 $t+1$ 个 Token”。每向前推进一个 Token，系统必须把**整个模型的全量权重参数从显存中完整读取一遍**，但这些参数仅与当前这 1 个 Token 的输入向量做一次内积。
* **算术强度：** 发生断崖式下跌。以 FP16 精度为例，每个参数占 2 字节，一次前向计算消耗约 2 次浮点操作（乘加），权重侧的算术强度仅为：

$$I \approx \frac{2 \times P \text{ FLOPs}}{2 \times P \text{ Bytes}} = 1 \text{ FLOP/Byte}$$

* **物理瓶颈：** 硬件处于极端的访存受限（Memory-Bound）状态。此时决定每秒吐字速度（Time Per Output Token, TPOT）的根本不是算力上限，而是内存控制器以多大的物理带宽把权重参数搬运到计算核心面前。

### 1.3 Roofline 模型的物理标定

以配备 80GB HBM3、显存带宽 3.35 TB/s、非稀疏 Dense FP16 峰值算力约为 989 TFLOPS 的 NVIDIA H100 SXM 为例：

* 其计算与访存的饱和平衡拐点（Roofline Knee Point）为：

$$I^* = \frac{989 \times 10^{12} \text{ FLOPs/s}}{3.35 \times 10^{12} \text{ Bytes/s}} \approx 295 \text{ FLOP/Byte}$$

* 在 Batch=1 的 Decode 阶段，实际算术强度仅为 **$1 \text{ FLOP/Byte}$**，远低于 $295$ 的饱和阈值。这表明，在单流自回归场景下，GPU 绝大多数浮点计算单元注定无法被饱和打满。

### 1.4 低 Batch 成为关键刚需场景

在传统数据中心，GPU 通过将数十上百个并发请求拼批（Batching）来摊薄单次权重读取成本。然而，下一代 AI 应用的落地边界正在打破这一前提：

* **端侧与个人算力：** AI PC、智能座舱、人形机器人等场景天然面向单一物理用户，请求**恒为 Batch=1**，无批处理请求可拼。
* **物理闭环控制：** 智能驾驶端到端控制回路要求在 10ms~33ms 内给出确定性动作预测，系统不能等待请求凑批，必须单流瞬时响应。
* **长思维链 Agent（Reasoning Chains）：** 具备深度推理能力的大模型在给出最终输出前，需在后台自发生成数千字中间推演过程。若单流速度停留在 30 Tokens/s，用户需等待数分钟；唯有实现 **300 ~ 800+ Tokens/s** 的极速自回归，才能将万字长推演压缩在秒级交互窗口内。

## 二、传统 GPU 面对低 Batch Decode 的“结构性内伤”

现代 GPU 建立在 SIMT 体系与分层存储体系之上。这一面向吞吐优化的架构在低 Batch 自回归场景下暴露了三重微架构矛盾：

### 2.1 延迟掩盖机制在低并发下彻底失效

GPU 的核心设计哲学是**利用海量线程并发（Thread-Level Parallelism, TLP）来掩盖片外存储的高访问时延**。当 Warp 0 发起 HBM 读取被挂起时，硬件调度器以单周期速度切换到 Warp 1 或 Warp 2 继续计算。

但在 Batch=1 场景下，单步输入的特征向量仅有 1 维，能够切分出的并发线程数断崖式下跌。活跃 Warp 数量枯竭后，硬件再无备用线程可供轮转调度，计算单元只能直接停顿（Stall），硬等数百个时钟周期的 HBM 访存数据送达。

### 2.2 实际算力利用率（MFU）暴跌

在标称拥有数百 TFLOPS 算力的顶级 GPU 上，低 Batch Decode 阶段的模型有效算力利用率（Model FLOPs Utilization, MFU）通常暴跌至 **5% ~ 15%**。

以单卡可完整容纳的 **LLaMA-3-8B（FP16 权重约 16GB）** 为例，在带宽为 3.35 TB/s 的 H100 上执行 Batch=1 Decode：

* 单步读取权重的物理传输下限为：

$$t_{\min} = \frac{16 \text{ GB}}{3350 \text{ GB/s}} \approx 4.78 \text{ ms/Token}$$

* 对应的单流生成理论上限约为 **209 Tokens/s**（若扣除 KV Cache 读写、Attention 计算、内核发射及驱动调度开销，实测通常在 100~150 Tokens/s 之间）。算力核心绝大多数时间处于饥饿空转，用户购买的庞大稠密算力在物理上无法转化为产出。

### 2.3 沉重的“冯·诺依曼税”（Von Neumann Tax）

通用计算架构的指令流驱动模式带来了高昂的控制开销：

* **控制面晶体管消耗：** 取指（Fetch）、译码（Decode）、动态分支预测、乱序缓冲以及多层级 Warp 仲裁电路持续消耗动态功率。
* **数据搬运的物理能耗代差：** 在先进工艺节点下，一次 16-bit 浮点加乘（MAC）计算耗能约为 **0.1 ~ 0.5 pJ**，而将 16-bit 数据通过高阻抗板级走线和物理 PHY 从片外存储搬运到寄存器堆，耗能高达 **100 ~ 200 pJ**。
* 在小算术强度下，GPU 绝大部分电能未消耗在有效张量运算上，而是耗费在数据搬运与指令调度的电荷充放中。

## 三、破局：空间数据流架构的微架构原理

数据流（Dataflow / Spatial Architecture）架构放弃了传统处理器的“时间复用（Temporal）”范式，转向“空间计算（Spatial Computing）”。

```text
传统 GPU (时间复用):
[统一计算单元 SM] ──第 1 拍: 算 QKV ──► [写回显存/缓存]
                  ──第 2 拍: 算 Softmax ◄── [从显存/缓存读出]
                  ──第 3 拍: 算 FFN ──► [再次写回]

数据流架构 (空间展开流水线):
[输入数据] ──► [PE 0: 算 QKV] ──(片内金属走线)──► [PE 1: 算 Softmax] ──(片内金属走线)──► [PE 2: 算 FFN] ──► [输出]
              (计算单元固定角色，数据像流水穿过芯片，无中间落盘)
```

### 3.1 空间计算替代时间复用

传统架构是“计算单元固定，指令与数据轮流进出”；数据流架构则是“在二维平面上直接把算子图铺开，数据流经阵列完成加工”。

* **流水线展开：** 芯片由二维分布的处理单元（Processing Element, PE）阵列构成。每个 PE 被配置为特定算子逻辑，计算任务沿着空间链路逐级流动。
* **驱动机制：** 计算的触发完全由“数据到达”驱动（Data-driven / Ready-Valid 硬件握手）或在编译期由静态时钟周期死锁编排（Cycle-deterministic），消除了全局取指译码与分支跳转开销。

### 3.2 物理级算子融合（Zero DRAM Spill）

在 Transformer 结构中，GEMV 之后密集交替着 RMSNorm、RoPE、SiLU、Softmax 等小算子。

* **GPU 的痛点：** 即使使用内核融合（Kernel Fusion），受限于每个计算单元内共享内存与寄存器堆的物理容量，层与层之间的中间激活值（Activations）仍需频繁在片内 L2 Cache 乃至片外显存之间反复写出与读回。
* **数据流的突破：** 上游 PE 算出的输出激活值，顺着片内微米级金属走线和局部分布式 FIFO 直接送入下游 PE 的输入端。**所有中间张量完全在片内空间完成逐级流动，实现算子间物理级零回写（Zero DRAM Spill）**，消除了大量无谓的总线与片外访存流量。

### 3.3 消除指令税与实现绝对确定性（Zero Jitter）

* **免除冯·诺依曼税：** 数据流阵列在执行大模型前向计算时，无动态指令译码，无乱序发射缓冲，也无需维持数百 KB 级的多端口通用物理寄存器堆。硅片上 70% 以上的面积与功耗直接分配给纯粹的乘加阵列与片上局部存储。
* **时间确定性：** 静态编排型数据流将所有仲裁与寻路完全前移至离线编译器。编译器精确锁定了每个数据包在第几个时钟周期流向哪个物理坐标。由于消除了硬件缓存未命中（Cache Miss）与运行时线程抢占，**单流时延的 P99 抖动比（P99 / P50）能够逼近绝对平直的 1.0**，满足硬实时闭环控制的严苛 SLA。

## 四、现实工程的取舍：两大技术流派与多维数据对比

在实际工程落地中，面对大模型动辄数十 GB 的存储体量，数据流芯片在“片上存储与片外存储的关系”上分化出两条截然不同的路线：

```text
                          ┌───────────────────────────┐
                          │     数据流芯片两大工程流派 │
                          └─────────────┬─────────────┘
                                        │
                 ┌──────────────────────┴──────────────────────┐
                 ▼                                             ▼
    【流派 A: 纯片上 SRAM 派 (Groq 为代表)】        【流派 B: 混合存储派 (Tenstorrent 为代表)】
    • 芯片无外部显存，权重全塞片上 SRAM            • 片上保留小 SRAM 缓冲，板载焊大容量 GDDR6
    • 片上带宽极高 (数十 TB/s)，单流狂飙           • 单卡容纳大模型，成本平民化 ($1,400)
    • 缺点：单芯装不下，跑 8B 必须整机柜           • 缺点：解码速度被 576 GB/s 外存带宽拉平 (~30 tok/s)
```

### 4.1 流派 A：纯片上 SRAM 流派（以 Groq LPU 为代表）

* **微架构哲学：** 彻底将 DRAM 赶出计算循环。芯片内部不接 HBM，也不接 GDDR，全片集成数百 MB 高速分布式 SRAM（如初代 GroqChip 集成 230MB，提供 80 TB/s 片内带宽）。
* **工程代价：** 单芯无法容纳任何主流 LLM。运行一个 LLaMA-3-8B（INT8 需约 8~10 GB 存储空间），**必须通过低时延片间网络将数十张卡组成机柜集群（GroqRack）**，将所有芯片的片上 SRAM 拼接成一个分布式存储池。它用极高的机架采购成本，换取单流极速。

### 4.2 流派 B：混合存储流派（以 Tenstorrent 为代表）

* **微架构哲学：** 承认单芯 SRAM 容量极限，走“空间计算阵列（Tensix Cores）+ 片外大容量低成本显存（GDDR6）”路线。以其主力桌面卡 **Wormhole n300** 为例，板载焊上 24GB GDDR6，片上仅保留 192MB SRAM 作为流水线乒乓双缓冲（Ping-Pong Buffer）。
* **工程代价：** 解决了容量问题，一张标准双槽 PCIe 显卡即可在台式机上跑下 8B 甚至 70B 模型。但由于自回归 Decode 必须频繁向片外显存换入权重，**其单流生成速度受制于 576 GB/s 的 GDDR6 物理带宽限制**。其实测速度回落到约 30 Tokens/s，但换来了仅 70W~100W 的超低运行功耗与极其平民化的价格。

### 4.3 跑 LLaMA-3-8B 的多维度工程数据对比

锁定单一基准模型（**LLaMA-3-8B, Batch=1**），对主流通用方案与两类典型数据流硬件进行工程对齐横评：

## 五、数据流架构的现实代价与工程壁垒

数据流芯片在换取能效、单流时延与确定性的同时，也承担了极其昂贵的工程代价：

### 5.1 SRAM 面积膨胀与制造成本矛盾

* **缩圈停滞：** 在 3nm / 2nm 等尖端制程下，逻辑晶体管仍在微缩，但 SRAM 位元面积（Bit-cell Area）的缩减已经近乎停滞。单 Die 能塞入的 SRAM 物理极限通常在 200MB ~ 500MB。
* **单位容量极度昂贵：** 1GB 的 HBM3 成本仅数十美元，而利用先进工艺裸晶刻蚀 1GB 片上 SRAM 的成本高达数千美元。纯 SRAM 方案要吞下大模型，硬件前置资本支出（CapEx）极高。

### 5.2 编译器的“地狱级”空间求解难度

传统 GPU 的运行时动态调度虽然消耗电能，但极大地降低了编程门槛。数据流芯片将所有调度责任前移给离线编译器，引发了严苛的软件挑战：

* **NP-Hard 空间规划：** 编译器不仅要切分算子，还必须求解数万个计算节点在物理二维网格上的放置（Placement）、无死锁网络路由寻路（Routing）以及纳秒级时钟周期的静态排程（Scheduling）。
* **动态控制流与 MoE 的噩梦：** 静态编排最怕“不确定性”。对于动态长短 Prompt、条件分支以及运行时动态门控路由的 **MoE（混合专家模型）**，静态编译器无法预知数据流向，极易产生大面积的流水线停顿气泡（Bubbles）。

### 5.3 软件生态与工程迁移惯性

CUDA、Triton 和 PyTorch 构筑了深厚的技术护城河。数据流芯片如果无法提供高度平滑的 MLIR 自动接入与分布式算子图下发能力，算法团队很难承担重构模型工作流的高昂迁移成本。

## 六、终局演进：Prefill-Decode 物理解耦与异构共存

体系结构的发展历史证明，通用性与专用性从来不是非此即彼的取代关系。大模型推理基础设施的终局形态，必然走向 **Prefill 与 Decode 物理彻底解耦（P/D Disaggregation）的异构系统**。

```text
                               【数据中心级 P/D 解耦异构拓扑】

            ┌────────────────────────────────────────────────────────┐
            │                  用户/业务请求进入 (Prompt)             │
            └───────────────────────────┬────────────────────────────┘
                                        │
                                        ▼
    ┌────────────────────────────────────────────────────────────────────────┐
    │ 1. Prefill 算力节点: GPU 的绝对主场 (Dense GEMM / Compute-Bound)       │
    │    • 硬件形态: 搭载大容量 HBM 的通用 GPU 节点                          │
    │    • 核心任务: 吞下长 Prompt，打满 TFLOPS 纯算力，极速生成 KV Cache      │
    └───────────────────────────────────┬────────────────────────────────────┘
                                        │
                                        │ 极速流式交付 KV Cache
                                        │ (走 PCIe P2P / CXL Fabric / RoCE 网络)
                                        ▼
    ┌────────────────────────────────────────────────────────────────────────┐
    │ 2. Decode 算力节点: 数据流芯片的终极舞台 (GEMV / Memory-Bound)          │
    │    • 硬件形态: 分布式大 SRAM / 空间流式流水线专用芯片/卡                │
    │    • 核心任务: 承接初始 KV Cache，以极高单字速率与极低能耗逐字生成回复   │
    │    • 运行特征: 极低 TPOT、极低能耗、近零抖动实时交付                    │
    └───────────────────────────────────┬────────────────────────────────────┘
                                        │
                                        ▼
            ┌────────────────────────────────────────────────────────┐
            │                   极速低时延流式响应返回用户            │
            └───────────────────────────┘
```

1. **Prefill 计算池（GPU 统领）：** 发挥通用 GPU 在高位宽 HBM 与稠密矩阵乘（Dense GEMM）上的绝对统治力，高并行消化长上下文 Prompt，压缩 TTFT。
2. **中间状态流式交付：** 初始计算生成的中间 KV Cache，通过 PCIe P2P、CXL 共享内存网络或跨节点 RDMA 直推，流式注入专用的 Decode 节点。
3. **Decode 计算池（数据流芯片统领）：** 专用数据流节点接管任务后，依靠空间算子流水、片内零落盘及超高片上带宽，以数百 Token/s 的高频自回归完成逐字生成，消灭推理长尾抖动。

这种分工解除了 GPU 在低 Batch 时的访存停顿，也规避了数据流芯片在全功能通用计算上的短板，使硬件在各自擅长的物理区间内释放最大能效。

---

大模型推理的技术演进，本质上是算法代数特征与底层物理定律反复博弈的结果。当算术强度随自回归退化到 1 FLOP/Byte 时，继续在传统指令驱动的时间复用架构上盲目堆叠浮点算力已不再具备经济效益。空间数据流芯片通过重构数据流动的空间拓扑、消灭冯·诺依曼税与解耦软硬件调度，在低并发、严苛 SLA 的推理深水区建立了明确的微架构优势。理解这种物理范式的转移，是设计下一代 AI 算力系统与软硬件协同架构的核心基石。
