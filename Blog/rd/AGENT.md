# AGENT.md —— `Blog/rd/` 区域的约定

写给在 `Blog/rd/` 里动手的 agent。**这份文件只约束我这一块**，
不要把它推广到别人的目录，也不要把别人的习惯抄进来。

> 每个人的环境和习惯不一样，各管各的。
> `Blog/<其他人>/` 和根级共享文件都不归这份文件管。

---

## 一、我的环境

| 路径 | 是什么 | 权限 |
|---|---|---|
| `~/Source` | 克隆下来的参考仓库 | 只读 |
| `~/Desktop/Codebase` | `~/Source` 的软链（同一份文件） | 只读 |
| `~/Desktop/control/` | 项目栈状态与入口脚本（ttsim / tt-metal / cosim-gpu） | 读；写前问 |
| `~/Desktop/Notes/` | 环境假设失效类问题 | 读 |
| `~/Desktop/cosim-gpu-note.md` | 虚拟化与设备接入笔记 | 读 |

---

## 二、边界

1. **只动 `Blog/rd/`。**
2. `Blog/<其他人>/` 是别人的区域，**只读**：改结论、改措辞、改结构、搬文件都不行。
   修死链和明显笔误也**先问**——该不该改不由我判断。
3. 根级共享文件（`home.md`、`home.html`、`开发指南.md`、`README.md`）不属于我，要改先问。
4. **未经我明确许可不要 commit。** 提交前把 subject 给我看一眼。
5. **不要 force push**；即便我要求，也必须用 `--force-with-lease`，并打印被覆盖的旧 SHA。
6. 提交信息用**英文** Conventional Commits（与本目录现有历史一致），一次一件事：
   subject 里出现 `and` / `并` / `；` —— 说明该拆。

### 2.1 未审区域：`draft/` 与 `vibe-product/` —— 默认静默忽略

这两个目录里的内容**准确性默认无保障**，是未审材料。因此：

1. **不要主动去审。** 不核查事实、不校对公式、不修错别字、不提改进建议——
   哪怕改起来很容易。这里的问题不是「你没发现」，是「不该由你去发现」。
2. **不要把它当事实来源。** 要取用其中的内容，按 §三 的权威顺序另找现场核实。
3. **只有我明确说要动，才动。** 其余一切情况**静默忽略**：
   不报告问题、不列问题清单、不询问「要不要我顺手修一下」。

## 三、事实纪律

**本目录里描述事实的文档默认不可信，包括我自己写的。** 这是纪律，不是态度问题。

> 例外：`draft/` 与 `vibe-product/` **连核查也不做**——那两个目录直接静默忽略（见 §2.1）。

### 权威顺序

```
机器状态（命令输出） > 源码 / 仓库现场 > ~/Desktop/control/ 的状态文档 > 本目录正文
```

### 硬要求

1. 写进文档的每个状态断言，**附核查命令或文件路径**。
2. **不要从旧文档转发事实**——要用，就先跑一遍命令。
3. 两份文档矛盾时，**以现场为准，并把矛盾本身记下来**，不要挑一份相信。
4. 进度类内容必须写时间点（"截至 YYYY-MM-DD"）；判断新鲜度先看 `git log` 和文件 mtime。

## 四、敏感信息

- **不写凭据**：密码、token、私钥、cookie、许可证号一律不进仓库（会被截图、转发）。
- **内部路径与内部状态可以写**（`~/Source/...`、构建命令、报错原文）——这本就是正文的形态。
- **对外时必须另起一份**，不要把这里的内容直接摘一段发出去。

## 五、文档格式

### 5.1 frontmatter 字段归属

| 字段 | 谁写 | agent 能否动 |
|---|---|---|
| `title` / `description` | 我 | 可改文字，但要与正文首行标题一致 |
| `tags` | 我 | 可以填 |
| `date` / `dateCreated` / `editor` | 编辑器生成 | **不许动**（无意义 diff，且影响站点排序） |
| `published` | 编辑器 / 我 | 不许动 |

### 5.2 LaTeX 分隔符（已因此返工过一次，钉死）

- 行内 `$...$`；块级 `$$...$$` **单独成段**，前后留空行。
- **不许** `\(...\)` 与 `$...$` 混用。
- 代码块、文件名、shell 里的 `$` **必须放进围栏**。
- `editor: markdown` 与 `ckeditor` 渲染行为不同，改完公式**在预览里看一次**。

### 5.3 落点与文件名

| 目录 | 放什么 |
|---|---|
| `vibe-product/` | **agent 主导产出、我未逐字审过**的完整文章 |
| `draft/` | 未写完或暂时无法归类的片段；**所有临时文件都在这里** |
| `script/` | 文章配套的代码或脚本 |
| `worklog/` | 当天的总结复盘，按 `YYMMDD.md` 命名 |

- 正式目录里的文件名必须是**最终标题**：不许 `a.md` / `b.md` / `xyz.md` / `test_*`。
- `vibe-product` 与 `draft/` 是**未审区域**，处理规则见 §2.1：判据是「**谁写的、有没有审**」，不是「有没有用」——
  拿它当"低价值"分类，会把正经工作笔记一起埋掉。

### 5.4 跨仓库引用

- 引用别的仓库的内容：**只放指针**，或注明来源仓库 + 抓取时间。
- **不要整篇复制**：它会漂移，其中的相对路径在本仓库里是死的。

## 六、反例（真实发生过的）

| 反例 | 错在哪 |
|---|---|
| `SOURCES.md` 写「tt-metal 未获取」，同一时期 `TT-STACK-STATUS.md` 写「已就位」 | 两份都在描述事实、都没核查，读者无从判断 |
| 文档要求「`libttsim.so` 同目录必须有 `soc_descriptor.yaml`」，而该文件实际不存在 | 把前置条件写进文档，却没验证前置条件本身 |
| 文档考据出推荐 `micah/native-sim` 分支，实际克隆在 `main`，且是浅克隆 | 结论写下来了，动作没跟上 |
| `b.md` 以临时名进了 git，随后又有一条 `normalize LaTeX delimiters` 返工 | 命名与分隔符都没约定，各返工一次 |
| `QF_philosophy.md` 整篇复制外部仓库的立论，文末指向本仓库不存在的路径 | 整篇复制必然漂移，相对路径必然变死链 |
| 本文件早先写着「这是公开文档」 | 与事实不符（内部知识库）；理由错了会让规则强度失准 |
| 早先把这份约定写到仓库根 `AGENTS.md` | 每个人的环境不一样，不该由我一个人替全仓库定规则 |
| 把 `vibe-product/` 里的文章当材料逐篇审读，还列了一张问题清单 | 那是未审区域，准确性无保障，**也不该由 agent 去审**；默认静默忽略（§2.1） |
